# 预期审查行为

以下内容用于最终结果的人工评估，不是标准答案。

## 应出现

- 将其作为系统/AI Infra 贡献审查，领域先验覆盖 KV Cache 分页、压缩、驱逐、CPU/NVMe offload、异步预取、长上下文稀疏保留和相关 serving runtime。
- 找出最接近的系统和策略，比较的不只是“是否也使用注意力”，还包括管理粒度、预测信号、存储层级、迁移时机、回退机制和优化目标。
- 把作用链拆开审查：早期访问摘要能否预测未来复用；预测是否能产生可执行的分层决策；迁移与预取是否能在 deadline 前完成；最终是否改善容量、吞吐和尾延迟。
- 把“早期注意力具有持续性”视为核心待验证假设，讨论跨层、跨头、跨任务、生成阶段和模型架构的非平稳性。
- 检查成本转移：注意力统计、预测器、块元数据、CPU 内存、PCIe/NVLink/NVMe 流量、后台迁移和额外采样是否抵消显存收益。
- 要求端到端且资源匹配的基线，至少观察 GPU KV 占用、最大并发、吞吐、TTFT、平均和 p99 token 间延迟、迁移 miss、主机内存/IO，以及模型质量变化。
- 检查工作负载是否代表真实请求长度、并发和访问模式，并进行不同硬件、带宽和模型规模下的敏感性分析。
- 区分局部预测准确率、微基准收益与真实 serving 价值；局部结果不能自动支持系统主张。
- 对尚无原型的性能目标保持条件化表达，并提出最先能淘汰错误机制的实验。

## 不应出现

- 仅因为预测 token 热度具有新意就接受端到端系统贡献。
- 只报告平均延迟或单请求 microbenchmark，忽略并发与尾延迟。
- 把 GPU 显存减少直接当作总资源成本下降。
- 未核对现有 KV eviction/offload 系统就声称是首个动态分层方案。
