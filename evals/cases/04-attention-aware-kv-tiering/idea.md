# 基于注意力持续性的分层 KV Cache 管理

长上下文大模型服务中，KV Cache 会持续占用 GPU 显存，限制可并发请求数。现有做法可以把部分 KV Cache 卸载到 CPU 或丢弃低重要性 token，但固定卸载规则很难适应不同请求：代码生成可能反复访问早期定义，文档问答可能集中访问少数证据段，而多轮对话的热点又会随生成过程变化。

我计划设计一个基于“注意力持续性”的分层 KV Cache 管理系统。系统在 prefilling 和解码早期收集低开销的分层、分头注意力访问摘要，预测各 token 块在后续窗口中再次被访问的概率，并把 KV 块动态划分为 GPU 热层、CPU 温层和 NVMe 冷层。运行时根据预测结果异步迁移和预取；当预测置信度不足或连续 miss 时，回退到保守驻留策略。为了避免逐 token 调度，管理粒度采用连续块，并限制每个解码周期的迁移预算。

当前已形成预测器、分层策略、异步预取和回退机制的初步系统设计，计划集成到开源 LLM serving runtime 中。实验将覆盖文档问答、代码生成和长对话，并比较 GPU-only、固定 CPU offload、基于最近访问和基于注意力重要性的策略。目标是在模型质量基本不变的情况下减少 GPU KV 占用、提高并发吞吐，同时不显著恶化首 token 延迟和 p99 token 间延迟。尚未完成原型，也不确定早期注意力是否足以预测后续访问。
