# IdeaPartner v1.1.0 Packaging Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Package IdeaPartner as a versioned Codex plugin while preserving direct standalone-skill installation, then verify a clean GitHub installation from the `v1.1.0` tag.

**Architecture:** Keep the repository root as the plugin root and reuse the existing `skills/research-idea-review` directory as the bundled skill. Add a plugin manifest, centralize the runtime version, add distribution-focused tests that exercise only the packaged files, and document both plugin and standalone installation paths. Do not change M1-M7 scientific behavior.

**Tech Stack:** Codex skill/plugin manifests, Python 3.11 standard library, unittest, GitHub Actions, Git tags.

---

### Task 1: Add the versioned plugin package

**Files:**
- Create: `.codex-plugin/plugin.json`
- Modify: `skills/research-idea-review/scripts/idea_review_runtime/__init__.py`
- Modify: `skills/research-idea-review/scripts/idea_review.py`

**Step 1:** Generate a minimal plugin scaffold with the bundled plugin-creator and inspect its manifest.

**Step 2:** Add the repository-root manifest with `name=ideapartner`, `version=1.1.0`, `skills=./skills/`, Apache-2.0 licensing, repository metadata, and concise install-surface metadata.

**Step 3:** Define `__version__ = "1.1.0"` in the runtime package and make the CLI version output consume that value.

**Step 4:** Validate the plugin and skill with the bundled validators.

### Task 2: Add distribution and installed-copy tests

**Files:**
- Create: `tests/test_distribution.py`
- Modify: `.github/workflows/ci.yml`

**Step 1:** Add a test that loads the plugin manifest, checks required paths, and asserts plugin/runtime version alignment.

**Step 2:** Add a test that copies only the plugin package to a temporary Unicode path and runs the installed CLI `--version`, `init`, and `status` commands.

**Step 3:** Keep the packaged runtime in CI compilation scope and run the complete test suite on Windows and Ubuntu.

### Task 3: Document installation and release boundaries

**Files:**
- Modify: `README.md`

**Step 1:** Document Python 3.11+, network requirements, explicit and implicit invocation, and direct GitHub installation from a release tag.

**Step 2:** Explain that the plugin manifest packages the skill for distribution while the standalone skill path remains available for case testing.

**Step 3:** Document update and removal guidance without requiring users to locate runtime internals.

### Task 4: Verify, publish, and install the release

**Files:**
- No source changes expected.

**Step 1:** Run compilation, all unit tests, the skill validator, the plugin validator, JSON parsing, link checks, and secret scanning.

**Step 2:** Commit and push `feat/package-v1.1.0`, create a PR, and merge only after checks pass.

**Step 3:** Create and push annotated tag `v1.1.0` on the merged `main` commit.

**Step 4:** Use the bundled skill installer with `--ref v1.1.0` and an isolated destination, then run the installed CLI smoke test and remove the temporary installation.
