# Three-stage artifact contracts

Read the section needed by the current task. JSON strings below denote types, not literal placeholders.

## Submission envelope

```json
{"task_id":"s1-plan","packet_id":"runtime-issued ID","payload":{}}
```

Packet IDs bind upstream versions. Never hand-author consumed_inputs or summaries of each input. For stage 3 a recheck_request may replace payload, never accompany it.

## Plan payload

- idea_claims: [{id, text, input_locator: {start: integer, end: integer}}]; line numbers are 1-based original input.
- boundaries: string[]; maturity: early/middle/developed; contribution_type: string; constraints: string[].
- working_assumptions: [{text, consequence_if_wrong}].
- review_questions: [{id, question, decision_impact, priority (optional)}].

At least one original claim and question. Unknown details are allowed. IDs use letters, digits, dot, dash or underscore (1–64 characters).

## Evidence batch (separate evidence-add command)

```json
{
  "batch_id":"b1",
  "question_id":"q1",
  "decision_impact":"Could change the novelty conclusion",
  "sources":[],
  "claims":[],
  "outcome":"Result of this targeted investigation"
}
```

For a new question add question: {id, question, decision_impact}. Existing questions cannot silently change meaning.

Source: {source_id, source_type, title, authors: string[], year, url, identifiers: {doi/arxiv/openalex}, edition (optional)}.
Allowed source_type: paper/dataset/benchmark/repository/official_docs/first_party_report.
Use HTTPS source URLs. Identity verification is generated by the runtime, never by the worker.

Claim: {claim_id, claim, question_ids: string[], source_refs: [{source_id, version}], relation, locator, inspection, limits}.
relation: support/contradict/context. inspection: full_text/official_document/abstract/snippet.
Replacement of a claim requires expected_version. Use canonical source aliases and current versions returned by evidence-add. New verified sources start at version 1; duplicate unchanged identities keep their version.
Unverified sources and snippet-only claims remain candidates. They cannot support review evidence_refs.
The runtime reports accepted/candidates/rejected, aliases, source_versions and cache_hits. A structurally invalid batch commits nothing.

## Review payload

- questions: [{id, question, decision_impact, outcome, evidence_refs}].
- judgments: [{id, dimension, statement, applicability, basis, evidence_refs, rationale, strongest_counterargument, uncertainty, next_action, input_locators (when input-based)}].
- closest_work: [{source_ref: {source_id, version}, overlaps, differences, consequence, evidence_refs}].
- decision: {status, rationale, scope, decisive_judgment_ids: string[]}.
- stop: {reason, unresolved_question_ids: string[], coverage_limits: string[]}.

dimension: value/contribution/mechanism/testability; account for all four.
applicability: assessable/provisional/not_yet_assessable/not_applicable.
basis: literature/researcher_input/inference. Literature requires active evidence; input-based judgments require locators.
decision.status: continue/revise/subsumed/not_viable/insufficient_evidence.
stop.reason: decision_supported/budget_exhausted/retrieval_unavailable.
evidence_refs everywhere: [{claim_id, version}].

Subsumed requires inspected substantive closest-work evidence and decisive judgments. Do not fabricate literature for a contradiction apparent in the researcher's own input.

## Report payload

- language: zh/en.
- structured_idea: object with six keys from idea-reconstruction.md, each an Item[].
- assessment: [{dimension, blocks: Block[]}], exactly the four dimensions.
- decision: Block; recommendations: Block[]; limitations: Block[].

Item: {text, provenance, input_locators: [{start,end}], evidence_refs}.
provenance: researcher_stated/evidence_supported/inferred/missing. Missing or inferred items have no evidence_refs.
Block: {text, judgment_ids: string[], evidence_refs}.
References must exist in the current review; important findings carry their evidence, including counterevidence. Put qualified uncertainty into text, not empty fabricated facts.

## Targeted recheck

```json
{
  "task_id":"s3-report",
  "packet_id":"runtime-issued ID",
  "recheck_request":{
    "question_id":"q1",
    "reason":"The comparison does not establish actual overlap",
    "affected_judgment_ids":["j1"],
    "needed_evidence":"Inspect the method and evaluation boundaries"
  }
}
```

A limit_reached response permits final payload using the same packet. The default limit is one. s2 resumes and supplies a revised current review; no additional role is created.
